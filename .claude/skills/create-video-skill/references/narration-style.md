# 旁白撰寫規範

要求是：**台灣腔、沉穩男聲、語氣平順緩和如說書、自然口語化、不要念稿、詳細說明技術內容**。

其中「沉穩」與「平順」由 TTS 參數負責（見 `tts-audio.md`），**「口語化」與「不像念稿」完全由腳本文字決定**。edge-tts 不支援 SSML，所以停頓、語氣、節奏只能寫進文字本身。

---

## 一、格式規則

`narration.txt` 一行一句，一句 = 一個 TTS 段落 = 一組字幕 cue 的來源。

- **每句 15–45 字**。低於 15 字語調會急促收尾；超過 45 字 TTS 會自行找地方換氣，位置往往很怪。
- **句尾一定要有標點**（`。`／`？`／`！`）。沒有標點的句尾，TTS 的音高不會下降，聽起來像話沒說完。
- **段落間空一行**，代表較長的停頓（合成時會加大句間間隔）。
- 不寫 Markdown 標記、不寫條列符號、不寫括號註解——會被逐字唸出來。

---

## 二、口語化：把「文件語言」翻成「講話語言」

文件是寫給眼睛看的，旁白是講給耳朵聽的。**直接唸文件必定像念稿。**

| 書面語（不要） | 口語（要） |
|---|---|
| 本系統採用分層架構設計 | 這套系統我們是拆成好幾層來做的 |
| 使用者須於此處輸入其帳號 | 你在這邊把帳號打進去就可以了 |
| 該功能之目的在於驗證權限 | 這個功能是要拿來確認權限的 |
| 如下圖所示 | 你看這張圖 |
| 綜上所述 | 所以整個講下來 |
| 請注意，此欄位為必填 | 這個欄位是一定要填的喔 |
| 若驗證失敗則回傳錯誤 | 如果驗證沒過，它就會回一個錯誤給你 |

**具體替換清單**：`之→的`、`其→它/你的`、`須→要`、`若→如果`、`並→然後`、`即可→就可以了`、`此→這個`、`該→那個`、`進行XX→XX`（「進行設定」→「設定」）。

---

## 三、說書感：節奏來自句子長度的變化

「如說書一般」的核心不是慢，是**節奏有起伏**。連續同長度的句子＝念稿。

**壞例（每句都 30 字左右，聽起來像機器）**：
> 使用者登入系統之後會進入主控台頁面。主控台頁面會顯示目前所有的裝置狀態。裝置狀態分為在線離線與異常三種類型。

**好例（長短交錯，有停頓有轉折）**：
> 登入以後，你會先看到主控台。
> 這一頁的重點，就是所有裝置的狀態。
> 狀態有三種：在線、離線，還有異常。
> 這三種我們等一下會一個一個看。

技巧：
- **短句放重點**。要強調的話單獨成句，越短越有力。
- **長句放鋪陳**。背景說明可以長一點，讓耳朵有緩衝。
- **用逗號製造呼吸**。`登入以後，你會先看到主控台。` 那個逗號就是一次換氣。
- **列舉用頓號加冒號**：`狀態有三種：在線、離線，還有異常。` 比 `狀態包含在線離線異常` 好唸太多。

## 四、不要念稿：加入「講話才有」的東西

念稿的人不會做這些，講話的人會：

**1. 承接詞開頭**（不要每句都直接進主題）
> 那我們接下來看…／好，這邊有個地方要注意…／其實這個設計是有原因的…／講到這個，就要提一下…

**2. 先預告再展開**
> 這一段有三個重點，我們一個一個講。

**3. 自問自答**
> 那為什麼要拆成兩層呢？原因很簡單，因為權限判斷跟資料存取，本來就是兩件事。

**4. 回指前文**
> 還記得剛剛那個 Token 嗎？就是在這邊用到的。

**5. 口語連接與語助詞**（台灣腔的關鍵，但**不要過量**）
> 對／那／其實／基本上／的話／就是說／喔／嘛

> ⚠️ 語助詞每 3–4 句出現一次就夠。每句都加會變成油腔滑調，反而不沉穩。

**6. 適度的評價與提醒**
> 這個坑我自己踩過，你要小心。／這一步很多人會漏掉。

## 五、詳細說明技術內容：三層講法

「詳細說明技術內容」不等於把參數唸出來。每個技術點都用**三層**講：

```
1. 這是什麼   → 一句話定義
2. 為什麼這樣做 → 設計理由、替代方案為何不好
3. 會踩什麼坑   → 實務注意事項
```

**範例**：
> 這邊用的是雙軌認證。
> 意思是同一個 API，網頁用 Session，外部程式用 JWT，兩種都收。
> 為什麼要這樣？因為如果只收 JWT，網頁裡面的 Vue 元件每次呼叫 API 都會被擋下來，然後前端攔截器又會把你導回登入頁，就變成一直跳回登入的無限迴圈。
> 所以這兩條路一定要打通，這是很多人會卡住的地方。

技術名詞的處理：
- **英文縮寫直接唸英文**：`API`、`JWT`、`JSON`、`SQL`。TTS 對這些處理得很好。
- **首次出現要解釋**：`JWT，就是那個帶在 header 裡面的 token`。
- **不要唸符號**：`user_id` 寫成「使用者 ID」，`app/services/` 寫成「services 這個資料夾」。底線和斜線會被唸出來或吞掉。
- **數字加單位**：`180` 寫成「180 像素」。

## 六、開場與結尾

**開場**（≤ 3 句，不要長篇自我介紹）：
> 哈囉，這一支影片我們要來看的是使用者註冊的功能。
> 我會從整個流程的架構開始，帶你一路做到實際的操作。

**結尾**（收束 + 提醒）：
> 好，到這邊註冊功能就完整跑過一遍了。
> 記得一個重點：註冊出來的帳號一定是一般使用者，管理員只能用指令建立。
> 這一支就到這邊，我們下次見。

## 七、自我檢查

寫完後逐項確認：

- [ ] 隨機抽三句**唸出聲**，像講話還是像念稿？
- [ ] 有沒有連續五句以上長度差不多？（→ 拆長句或合併短句）
- [ ] 有沒有殘留書面語？搜尋 `之`、`其`、`須`、`即可`、`本系統`、`如下`。
- [ ] 每個技術點是否都講了「為什麼」，不只「是什麼」？
- [ ] 語助詞是否過量？（每 3–4 句一次為上限）
- [ ] 每句是否都有句尾標點？
- [ ] 有沒有超過 45 字的句子？
