# 系列海報風格規格 —— 樂高積木科技風

單元海報一律走**樂高積木科技風**：積木搭建的技術意象、樂高原色、扁平明亮、版面精簡。
新的一張要「看起來就是同一套」，寫提示詞時逐項對齊。

設計原則兩條，牴觸時以這兩條為準：

- **簡易**：整張海報最多 5 個文字區塊，字大、留白多。寧可少講一句，也不要把講義塞滿版面。
  （圖像模型畫小字中文很容易糊掉或出簡體字，區塊少、字大是最有效的防呆。）
- **亮麗**：白底或淺色漸層，樂高原色高彩度大面積鋪陳，扁平無材質紋理、無筆墨、無書法。

## 硬規格

| 項目 | 值 |
|---|---|
| 尺寸 | 1024 × 1536（直式 2:3） |
| 格式 | PNG，從 ChatGPT 取回的原始檔（約 2～4 MB） |
| 文字 | 繁體中文，不可出現簡體、錯字、變形字；英文技術名詞維持原文（SQL Server、RAG、Embedding…） |
| 檔名 | `NN 標題.png`，兩位數編號 + 半形空格 + 主標 |

## 視覺基調

- **底圖**：純白或極淺的藍→白漸層，乾淨無紋理。可鋪一片很淡的樂高圓凸點（stud）陣列當底紋。
- **主色**：樂高原色高彩度四色 —— 紅、黃、藍、綠；以**藍**為主色（標題磚條、主結構），
  **黃**為強調色（重點磚、箭頭），紅與綠只做點綴。淺灰只用於陰影。
- **質感**：扁平向量風、塑膠亮面、圓角、柔和的單向投影。**不要**寫實攝影、不要金屬反射、不要水墨或紙質肌理。
- **主體**：畫面中段一組**樂高積木搭建的技術意象**（依單元主題：伺服器磚塔、資料庫圓柱、
  文件磚堆、向量方塊格、對話泡泡磚、齒輪磚…），旁邊站一個**樂高小人講師**（戴眼鏡、拿平板或工具）。
- **連結線**：各區塊之間用**樂高顆粒串成的線條或箭頭**銜接流程方向，取代任何光暈或放射線。

## 版面骨架（由上而下，最多 5 個文字區塊）

1. **標題磚條**：頂部一條藍色 2×8 長條積木，內寫 `Section NN｜<主題>`，白色粗體大字。
2. **副標＋時間行**：磚條正下方一行深灰副標（一句白話主旨），其下一行小字
   `120 分鐘｜觀念 20・示範 25・實作 65・驗收 10`。
3. **主視覺**：中段的積木技術意象＋樂高小人講師，佔版面約 40%，是整張圖的視覺重心。
4. **技術名詞磚**：3～5 塊 2×2 彩色積木橫向或錯落排列，每塊上面一個技術名詞，
   下方掛一行極短白話註解（不超過 12 字）。
5. **驗收磚條**：底部一條黃色長條積木，內寫該單元的**驗收成果**一句，深色粗體字。

沒有側欄直排文字、沒有印章、沒有正解／誤解對照框、沒有練習方框 —— 這些在舊版佛學系列裡用，
樂高風一律拿掉，改由第 4、5 點承擔。

## 從講義取材的對應

對應本課程教案（`SQL_Server_2025_RAG_ASPNET_Core_MVC_30小時課程教案.md`）的單元大綱欄位：

| 海報欄位 | 講義來源 |
|---|---|
| Section NN／主題 | 檔名前綴與 H1（教案「單元大綱」表的 `Section` 與 `主題`） |
| 副標 | 該單元的學習目標，濃縮成一句白話 |
| 時間行 | 固定為 `120 分鐘｜觀念 20・示範 25・實作 65・驗收 10`（教案 5.1 的時間配置） |
| 主視覺意象 | 該單元的核心技術物件（資料庫、PDF 文件、向量、路由、聊天室…） |
| 技術名詞磚 | 「教學與實作內容」裡的關鍵技術詞（Repository、Embedding、`VECTOR_DISTANCE`、DiskANN…） |
| 驗收磚條 | 「單元驗收成果」該格原句，必要時縮短 |

講義若另有「常見錯誤」段落，**不另開區塊**，挑最重要的一項併進技術名詞磚的註解裡。

## 標題再創作

海報主標不是照抄 md 檔名，而是短句化：

| 講義檔名 | 海報檔名 |
|---|---|
| `01_專題導入與環境建置.md` | `01 RAG 起手式：環境建置.png` |
| `03_三知識庫資料模型.md` | `03 三庫同構的資料模型.png` |
| `06_Embedding與SQL向量儲存.md` | `06 把文字變成向量.png` |
| `08_文件增量更新與版本發布.md` | `08 重傳不重算.png` |
| `11_TypeSafe智慧分類與路由.md` | `11 問題該送去哪一庫.png` |
| `15_整合驗收與部署.md` | `15 交付一套會回答的系統.png` |

規則：4～12 字、動詞句或冒號式副標、可保留英文技術名詞、避免與前一張重複句型。
